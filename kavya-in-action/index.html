Decision principles

Cloud escalation is conditional, not the default route.

Offline path

Coordinates agree

Use the stronger valid local detection. Keep the action inside the existing Accessibility authorization and verification flow.

Escalation path

Coordinates disagree

When confidence is low or both models disagree above 50%, request help from an already configured, available vision provider.

How Kavya works

A single observation travels through a controlled pipeline.

1
Capture one fresh observationScreenshot, timestamp, dimensions, app context and available UI hierarchy share one observation ID.
2
Run both local modelsSmolVLM2 and Florence-2 analyze the same frame independently. Model-specific outputs are normalized.
3
Resolve consensusCompare calibrated confidence and normalized target bounds with tolerance; never compare raw pixels only.
4
Escalate only when neededUse only a compatible provider that is already configured and available. No provider is assumed.
5
Match the Accessibility nodeRe-check freshness and match bounds, text, content description or resource ID where available.
6
Act and verifyExisting authorization gates the action. A fresh post-action observation verifies the outcome.

Reliability guardrails

Keep model execution coordinated and prevent stale or duplicate actions.

Observation isolation

Every result belongs to one observation ID. Older results cannot overwrite newer screenshots.

Failure isolation

A local model failure does not crash the other model or the assistant.

One action authority

Vision adapters return detections; only the central orchestrator can authorize an action.

Truthful fallback

If no configured vision provider is available, report that state. Never invent a cloud result.
